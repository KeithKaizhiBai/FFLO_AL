Warm-up exact calculation

Where the Initial Dataset Comes From

Hamiltonian and free-energy scan

The warm-up dataset is not generated by ML. It is an exact BdG scan on a prescribed \((k_B T/t, J_A/t)\) grid. For each point, the code builds the BdG Hamiltonian and searches over the pairing amplitude \(\Delta\) and FFLO momentum \(q\).

\[ \mathcal{H}_{\mathrm{BdG}} = \frac{1}{2}\sum_k \Psi_k^\dagger H_{\mathrm{BdG}}(k)\Psi_k + \frac{N}{U}\lvert \Delta_q\rvert^2 \] \[ H_{\mathrm{BdG}}(k) = \begin{pmatrix} h(k+q/2)-\mu & \Delta_q \\ \Delta_q^* & -\sigma_y h^T(-k+q/2)\sigma_y+\mu \end{pmatrix} \] \[ h(k)=\xi(k)+\mathbf{d}(k)\cdot\boldsymbol{\sigma}, \qquad \xi(k)=t\cos k, \qquad \mathbf{d}(k)= (0,\lambda_y\sin k,\lambda_z\sin k+J_A\cos k). \]

The exact label is assigned only after the free energy is minimized:

\[ (\Delta_{\mathrm{opt}},q_{\mathrm{opt}}) = \arg\min_{\Delta,q}\Omega(\Delta,q;k_B T/t,J_A/t). \]

Why this is expensive

A direct scan evaluates many trial \((\Delta,q)\) states and many momenta \(k\) at each thermodynamic point.

\[ C_{\mathrm{scan}} \sim N_{kT}N_{J_A}N_\Delta N_q N_k d^3, \qquad d=4. \]

With the current warm-up grid this is about \(3.44\times10^9\) \((\Delta,q)\) trials and \(2.76\times10^{12}\) small BdG matrix evaluations over \(k\). This cost is why the later ML stage selects only a small batch of new exact points per iteration.

Selection logic

Two Routes Feed the Same Exact Oracle

Route A

Dense-Grid ML Acquisition

Purpose: discover uncertain, risky, or under-covered regions across the admissible candidate grid.

  1. Generate a finite candidate grid in (kBT/t, JA/t).
  2. Apply the physics mask, including JA <= JAref(kT) + 0.08.
  3. Predict observables, phase probabilities, and uncertainties with the trained MLP ensembles.
  4. Compute the acquisition score \(S(x)\) for every admissible candidate.
  5. Rank candidates and apply duplicate, existing-distance, cooldown, and diversity exclusions.
Post-training score
\[ S(x)=\sum_i w_i T_i(x). \]

The weights \(w_i\) are fixed hyperparameters in the current implementation.

Directly controls full exact-call batch selection rank and trace
Diagnostics

Exact Boundary Extraction

Current code path: exact phase brackets are extracted only to diagnose the accepted dataset. They do not feed selected_points.csv.

  1. Read the current cumulative accepted exact dataset.
  2. Assign exact phase labels using \(\Delta_{\mathrm{opt}}\) and \(q_{\mathrm{opt}}\) thresholds.
  3. Bin exact points by kBT/t with width 0.005.
  4. Within each bin, sort points by JA/t.
  5. Find neighboring exact points whose phases straddle normal/SC or uniform_SC/FFLO.
  6. Write boundary segments and displacement diagnostics.
Diagnostic boundary estimate
\[ x_{\partial} = x_{\mathrm{left}} +\lambda \left(x_{\mathrm{right}}-x_{\mathrm{left}}\right), \qquad x=(k_B T/t,J_A/t). \]

The diagnostic estimate is recorded for analysis, not sent to the exact oracle.

Relationship between the two

The regressor and classifier learn from the same exact dataset, but they are trained with different losses because continuous observables and categorical phases are different statistical objects.

RMSE values are validation diagnostics. They are not summed into a joint loss with cross entropy.

How predictions become an acquisition score

1

Predict on the candidate grid

For each admissible candidate \(x\), the regression ensemble gives \(\hat{\Delta}_{\mathrm{opt}}(x)\), \(\hat{q}_{\mathrm{opt}}(x)\), \(\hat{\eta}(x)\), and current predictions. The classifier gives phase probabilities \(p(c|x)\).

2

Convert predictions to score terms

The code derives uncertainty and boundary-proximity terms such as \(U_{\mathrm{cls}}(x)=1-\max_c p(c|x)\), \(U_{\mathrm{reg}}(x)\), \(B_\Delta(x)\), \(B_q(x)\), \(B_\eta(x)\), \(G(x)\), \(E_q(x)\), and \(E_{\mathrm{ext}}(x)\).

3

Combine terms with fixed weights

\[ \begin{aligned} S(x)=& w_cU_{\mathrm{cls}}(x) +w_rU_{\mathrm{reg}}(x) +w_\Delta B_\Delta(x) +w_qB_q(x) \\ &+w_\eta B_\eta(x) +w_gG(x) +w_dD(x) +w_{\mathrm{edge}}E_q(x) +w_{\mathrm{ext}}E_{\mathrm{ext}}(x). \end{aligned} \]
4

Mask, sort, and select

Candidates outside the physics mask or exactly matching existing exact data are removed. Nearby existing data and already chosen batch points apply soft repulsion factors. The remaining dense-grid candidates are selected by the corrected score.

What changed

The fixed midpoint quotas have been removed from the selected exact-call path.

The MLP predictions define the main acquisition score. Exact duplicate coordinates are masked. Candidate proximity to previous exact data and to the current batch is handled by soft repulsion.

Boundary extraction remains useful for reading the phase diagram, but it no longer creates midpoint candidates.

Next to do

Improve the Acquisition-Only Selector

Keep midpoint selection disabled

Midpoints are based on geometric brackets in the exact dataset. They are useful for bisection, but they do not let the ML model decide where a new exact call would most reduce uncertainty or error. The current implementation disables midpoint quotas and uses ML-guided acquisition for the exact-call batch.

Reconsider the role of radius

A fixed radius is a sampling-density control, not a physical convergence rule. It should prevent redundant exact calls, but it should not force a rigid grid-like pattern or block useful points near a rapidly changing boundary.

Make ML contribute more to point choice

At present the MLP learns observables and phases, while a hand-written acquisition formula makes most of the selection decision. The next stage should make the learned uncertainty, boundary probability, local error estimate, or expected improvement directly control the sampling density.

Keep the quality gate unchanged

The exact oracle and quality gate remain essential. A selected point still becomes useful training data only after exact BdG evaluation and q/Delta reliability checks.

Brainstorming

Executable Redesign Options

Option A

Pure ML acquisition with adaptive radius

Remove midpoint pools. Score all admissible dense-grid candidates using the trained model, then adapt the exclusion radius locally: smaller near high uncertainty or high predicted boundary gradient, larger in flat regions.

\[ r(x)=r_{\min} + \frac{r_{\max}-r_{\min}} {1+\alpha U(x)+\beta G(x)}. \]
  • Implementation: replace fixed \(r\) in dense-grid selection with candidate-dependent \(r(x)\).
  • Benefit: keeps ML as the driver while reducing repeated and overly rigid point choices.
  • Validation: track duplicate rate, new unique points, boundary displacement, and validation error per exact call.
Option B

Boundary probability field from ML predictions

Use the classifier and regressor to form a continuous probability field for being near a target phase boundary, instead of selecting midpoint brackets.

\[ P_{\partial}(x) = P_{\mathrm{cls,boundary}}(x) + \lambda_\Delta B_\Delta(x) + \lambda_q B_q(x). \]
  • Implementation: build a boundary-proposal pool from ridges of \(P_{\partial}(x)\).
  • Benefit: selects along ML-predicted boundary curves, including regions outside current exact brackets.
  • Validation: compare proposed boundary ridges against later exact labels and phase-boundary displacement.
Option C

Learn a utility model for point selection

Keep the physical MLPs, but add a small secondary model that learns which past selected points actually improved the next exact dataset or reduced validation error.

\[ \widehat{U}_{\mathrm{gain}}(x) \approx \Delta \mathrm{error}(x) \quad\text{or}\quad \Delta \mathrm{boundary}(x). \]
  • Implementation: log candidate features and post-oracle outcomes, then train a lightweight gain predictor.
  • Benefit: acquisition weights become data-calibrated instead of purely hand chosen.
  • Validation: A/B test against the current hand-weighted acquisition using the same exact-call budget.
Option D

Batch selection by expected information and diversity

Select a batch by maximizing a utility objective for the whole batch, rather than greedily taking one high-score candidate at a time under a fixed radius.

\[ \mathcal{B}^\star = \arg\max_{\mathcal{B}} \sum_{x\in\mathcal{B}} S_{\mathrm{ML}}(x) - \gamma \sum_{x_i,x_j\in\mathcal{B}} K(x_i,x_j). \]
  • Implementation: use greedy submodular selection or k-center selection weighted by \(S_{\mathrm{ML}}(x)\).
  • Benefit: controls repeated points without relying on a single hard radius threshold.
  • Validation: check spatial coverage, selected-score distribution, and accepted exact-point yield.
